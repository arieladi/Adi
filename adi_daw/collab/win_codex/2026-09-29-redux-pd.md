# Redux — manual checklist before implementation

Mission 4, delegated by win. Branch: `codex/redux-pd`. This checklist is
written before the DSP or patch. Reference: Live 12 manual, chapter 28.30,
printed pages 615–616 (`reference/DOCS/DAWs/Ableton_live12/28d ...pdf`).
The text below paraphrases the chapter; no reference artwork is copied.

## Acceptance checklist

- [ ] Rate reduces the sampling clock; with filters disabled, a sine above
  the reduced Nyquist frequency aliases to the predicted frequency.
- [ ] Jitter varies that clock independently across stereo channels, producing
  noise and width; resetting a render repeats its result deterministically.
- [ ] Pre limits bandwidth before the hold stage and reduces jitter-induced
  stereo differences; Post suppresses images after it.
- [ ] Post-Filter Octave moves the post cutoff relative to half of Rate.
- [ ] Bits reduces amplitude resolution; extreme reduction destroys dynamics.
- [ ] Shape gives quieter amplitudes finer resolution than louder amplitudes.
- [ ] DC Shift offsets the signal before quantization and changes distortion.
- [ ] Dry/Wet interpolates between dry and processed audio; 100% supports sends.
- [ ] The top-level stereo Pd patch declares every parameter with `adi.param`
  and connects `adc~` through the compiled-in external to `dac~`.
- [ ] Measurements cover the processing claims, identical output for block
  sizes 32 through 4096, and zero allocations in processing.
- [ ] LibPdEngine opens the real patch without console errors, produces a
  measured tone (far-bin floor checked first), and renders only to files.
- [ ] Human side-by-side acceptance (ADR-0108): pending win/director session.

Bespoke BitcrushEffect or Airwindows DeRez and requires our own jitter.

`b6eef0af60cd32641b09837096e41bbcdb030341`,
`src/autogen_airwin/DeRezProc.cpp` (Airwindows MIT header retained if adapted).

quantization and dither. Source selection awaits win's clarification.

The chapter specifies names and behavior but does **not** give complete ranges
or default values. The page 615 picture shows an example, not a declared
default preset. Proposed ADI values must be labelled as such, or replaced by a
verified Live parameter dump; no fabricated manual attribution.
