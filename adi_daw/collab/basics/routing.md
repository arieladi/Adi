For SC-261, decide what plays when the saved physical Main pair is unavailable. The draft falls back to the first complete stereo pair. I recommend retaining the saved selection, keeping any surviving member on its own physical output, and keeping Main silent when both members disappear. An automatic fallback could send audio to an unexpected physical output. SC-431 sets Cue behavior. Win's parked review has a Main fixture for the silent case and the surviving left output. [Parked review](https://github.com/arieladi/Adi/commit/b33d59e000ae763769bbbd5b5b60989b63621789)

For SC-253, I recommend disabling Show Take Lanes when the track has no takes and letting Insert Take Lane open the first lane. I also recommend matching Live's documented behavior of exiting Automation Mode when showing or inserting takes. The draft currently keeps automation lanes and takes visible together. Win's parked review covers the empty-track shortcut and menu. [Live take-lane controls](https://www.ableton.com/en/live-manual/12/comping/#inserting-and-managing-take-lanes)

The parked review also identifies checked iterators in the Cue and live MIDI callbacks and a recording-owner lock that can obstruct take discard on Windows filesystems. These are Windows Debug and recorder follow-ups. They have no new local runtime result.

SC-404 landed with the port and channel in the existing `routing.channel_map` CBOR map. The earlier dedicated table was staged for schema 1.28 in #823. Follow-up work should build on the routing row now used by saved projects.

Reserve a schema minor for SC-277's native track-to-track input and output states. I recommend the MX-25 format with foreign keys on both tracks, a source tap for Audio From, post-effects MIDI From, and a track-owned choice for Sends Only and No Output. The audio input and output mode DDL is staged. Existing `routing` rows handle explicit audio destinations. For nonexclusive MIDI, I recommend separate MIDI To rows with foreign keys on source and receiver, while a track can keep a single MIDI From selection. Use an event-only graph edge and account for held notes by source and sink when a route changes. Pedals share state at the receiving channel and need to stay active until the last source releases them. The current Main route carries audio and forwards its original input events. An after-effects tap needs MIDI output forwarding from the VST3 and CLAP hosts.

For SC-406, I recommend storing the optional hardware zone and member count on the landed MIDI routing row as versioned channel-map fields. The draft's staged SQL predates that encoding. Win's 28 November log records the SC-277 and SC-406 format rows as owed. For the hardware worker, retain ordered zone setup and teardown as complete RPN transactions tied to the exact output, with old note and pedal releases cleared before opening the new zone. I recommend project-owned plug-in zone storage keyed by device instance, so two instances of the same plug-in can keep different configurations after reopening. The draft uses existing MIDI To and device MPE menus. [Win's landing log](https://github.com/arieladi/Adi/blob/bdcccb3e0/adi_daw/collab/win.md) [Ableton plug-in MPE guide](https://github.com/Ableton/ableton.github.io/blob/main/plugins/mpe-support-plugins.md#example-cc-event-sequences-to-indicate-mpe-mode-and-zone-configuration)

For SC-269 I recommend placing the recorded Main stream on the compensated project timeline so it lines up when played alongside its source. Verify the policy with an impulse test that forces real Main-path compensation. Check the physical output and the saved clip offset separately. Include impulses just before punch-in and punch-out and distinct impulses at the end of each loop pass. The input and Main taps currently share a recording clock, so correcting the saved linear clip offset alone would still lose delayed punch tails or assign them to the wrong loop pass. Live documents the Main tap and recording-track suppression in its Resampling section. Its latency guidance describes monitoring settings separately.
