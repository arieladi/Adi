## For the director

- R12 is still open. I recommend leaving the copied track disarmed until it is explicitly armed. The branch sets that policy in `kCopyArmState`. Copies of frozen tracks use their editable source because a rendered freeze cache belongs to the original identities.

- R13 is still open. I recommend double-click and Delete reset to 0 dB for the fader and silence for a send. The gestures are provisional constants in the mixer.

- SC-85 used the proposed ADI JSON format under ADR-0258 d18. Each file contains a device format, UID and shell identity, a display name, normalized parameters, and optional named base64 state streams verified by BLAKE3. The device groups use a stable identity key. Track placement and automation stay in the song. The branch uses the configured User Library. SC-135 owns the first-launch default.

- R50 is still open. I recommend keeping the existing refusal when a known instrument is double-clicked with an audio track selected until the Live reading confirms automatic MIDI-track creation. The branch builds the known-instrument path with no selection and records the audio-track choice in `kNewMidiTrackWhenAudioSelected`.

- SC-288 Group needs the rack playback and structural operations in DEV-01 and DEV-03. The current engine skips rack children. Both feature branches conflict with the landing stack, and DEV-01 still needs the ADR-0253 playback corrections. I recommend wiring Group after those revisions land so grouping an instrument or effect keeps it audible.

- SC-281 needs a portable default track that carries devices, plug-in state, and media into another project. I recommend defining how it maps sends before applying it at track creation. Sample settings already save by content hash under TM-MD-04. I recommend wiring Clip View Save and both import paths there while keeping ordinary drops atomic.
