## Decided — do not re-litigate these

- **The UI never touches `SnapshotPublisher`.** ADR-0201: nothing crosses threads, the audio thread never reads an `engine::Snapshot`. No publisher, no epoch, no `collect()`. `ProjectView` is the one cell; a frame takes `current()` **once** and hands that pointer to every component.
- **Two windows may briefly sit one generation apart. Accepted** (director). The rule that makes it safe: **anything crossing windows re-reads `ProjectView::current()` when it LANDS and never carries a snapshot between windows.** A drag from a floating window must obey this.
- **The key map is TWO homes.** Command shortcuts are **app-scoped** in `src/adi/settings/`'s `shortcuts` page. Live's **Key Map mode** (computer keys → parameters) is **project-scoped**, in `controller_maps` with a keyboard source, beside the MIDI Learn bindings (ADR-0195 d3).
- **`MainSplit` is not a `StretchableLayoutManager`.** A width belongs to the **panel** and follows it across a swap; a swap reorders and never reconstructs; one that does not fit **refuses with a message**.
- **Deleting a device closes its floating window; undo restores the device, not the window.** Implemented as a **poll** of `Session::entryFor(id)->retired` at the top of the frame — there is no push event, and `Session::refresh` is no longer UI-initiated only (`gain_stage.cpp:171`).
- **169 px is still UNVERIFIED** and must not become a constant. ADR-0200 d5 requires it be a desktop default, not a component constant.

## Traps that already cost time

1. **`publisher.peek()` is a use-after-free for any non-announcing caller.** A design round proposed copying through it. It returns a bare pointer, sits under an *audio thread* header, and `collect()` can free the object between the load and the read. `host.hpp` guards this shape and `test_host.cpp` regression-tests it. Do not reintroduce it.
2. **Re-pin every citation AFTER a merge.** This bit twice in one day: `session.hpp` shifted two lines and invalidated verified line numbers, and `tools/test_all.sh` changed behaviour under me — I shipped a wrong instruction into the plan because I read it before a merge and not after.
3. **`tools/test_all.sh` does NOT fail on a README headline mismatch.** It prints a note. **Leave `README.md:9` alone in a PR** — win updates it on main. This is deliberate: every PR touching that line turned the next one red.
4. **A planted defect only counts when the file CHANGED and the build SUCCEEDED.** A plant that does not compile leaves a stale binary that cheerfully reports PASS. Verify the restore too, byte-identical.
5. **A plant that PASSES has found dead code.** It happened here: `OpSubmitter` stripped `selBefore` from non-first ops, and removing that changed nothing because `ops.cpp:389` already does it. The line was deleted.
6. **Never `git add -A`.** The repo is public, the tree carries unrelated untracked work, and `adi_daw/third_party` is a symlink. Stage explicit paths.
7. **The checkout is in iCloud-synced `~/Documents`.** It manufactures `"name 2.ext"` conflict copies — 14 were deleted from `adi_daw/tools/` today, and more remain elsewhere. Identify them with `git ls-files`, **never by name pattern**. The permanent fix is the director's: move the checkout out of iCloud. This is the same root cause that made Gatekeeper refuse the unsigned fixture bundles earlier.

## For Windows specifically

- **CI has no Linux or Windows GUI job yet.** One job builds with JUCE (`ci.yml:653`, macOS + Windows), `ADI_WITH_JUCE` defaults **OFF**, and `CMakeLists.txt:900-905` requires the JUCE-off build to stay green on every ABI. **A GUI test binary lives behind `ADI_WITH_JUCE` and cannot join the default required matrix.**
- The JUCE **GUI modules already compile** in that job (`juce_audio_processors` → `juce_gui_extra` → `juce_gui_basics`), so adding a GUI target is less work than it looks.
- **Short build paths on Windows.** No CI job sets a `working-directory` or any short-path workaround; the build survives in `D:\a\Adi\Adi` with ~169 characters to spare under `MAX_PATH` **by luck**. `tools/build-juce.bat:13-14` already warns about this for local checkouts. GUI targets add deeper generated paths — add the guard rather than relying on GitHub's layout.
- **Offscreen rendering needs no X display on Linux** (X11 is `dlopen`'d, never linked) — but that is a *source-level* conclusion, not an executed one. Settle it with a small console app under `env -u DISPLAY` before writing the CI leg.
- **Pass `SoftwareImageType{}` explicitly** to `createComponentSnapshot`, or macOS and Linux snapshots differ in pixel format for reasons unrelated to the UI.
- **JUCE ships no mock peer.** Synthesised *mouse* events through the public virtuals bypass hit-testing, capture and click counting — they test the handler, not the interaction. **Keyboard is real** (`keyPressed` is public), which is what matters, because ADR-0129's gate is entirely keyboard.
