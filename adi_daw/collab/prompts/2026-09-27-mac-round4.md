2. ADR-0188 d8 -- no Pd externals from disk. ADI's externals are compiled into the engine and registered
   with libpd as built-ins; no .dll, .dylib or .pd_darwin is ever loaded, so a patch cannot bring native
   code into the process. Your LibPdEngine adds the patch's own directory to the search path, and vanilla
   Pd resolves compiled externals through that same path: a .pd_darwin sitting next to a project's patch
   would load. Make loading a compiled external impossible (a loader that refuses, or libpd built without
   dynamic loading -- your choice, say which), and prove it with a test: a patch naming an external that
   sits beside it fails to create the object, and the engine reports it. [adi.array] as a vanilla MIT
   abstraction is exactly right, and abstractions keep resolving through the path.
3. ADR-0188 d3 -- the Pd runtime rules your engine follows:
   - a range change keeps the stored real value, clamped, and recomputes the normalized position, in the
     same device.loadState, so one undo restores both;
   - modulation is evaluated by the DAW and sent into [adi.param] on the audio thread before the block,
     summed and delay-compensated, and only to receive names the patch declared (a name Pd has not seen is
     created with an allocation). A message lands at a block boundary, so a modulated value arrives once
     per 64 samples; audio rate inside a patch would be an [adi.param~], later;
   - transport is [adi.transport $0], a vanilla MIT abstraction beside adi.param.pd: playing or stopped,
     BPM, time signature, bar, beat, and ticks within the quarter note. Pd's floats are 32-bit, and ADI's
     5,765,760 ticks per quarter pass 2^24 within three quarter notes, so an absolute tick count is never
     sent. It is not built; if the analyser needs transport, build it in #138 or a follow-up, against
     that field list.
4. The patch editor on plugdata (ADR-0145 d8) ships externals of its own (ELSE, cyclone). When the editor
   is built it must mark every object the engine does not have. Nothing for #138 unless it already
   touches the editor.
