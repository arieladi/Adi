# mac — check and walk, 27 November 2026

**Why.** Nobody has built or driven ADI on a Mac outside CI since September. Every landing stack waits
about an hour for the macOS checks, and a failure that only Apple's compiler shows costs a second hour.
The nine steps that ended the hold (ADR-0255 d1) were walked on Windows 10 and 11 only. You run on the
director's Mac and do three things, in this order. Read `collab/prompts/2026-11-27-basics-howto.md` for
how the weekend's sessions work.

**Your report:** `adi_daw/collab/basics/mac.md` on the branch `basics/mac-log`, pushed after every item.

## 1. main on this Mac, once

Build as CI's macOS legs do (`.github/workflows/ci.yml`, the main matrix, and `ui.yml`, the GUI shell
leg): Ninja, JUCE on, warnings as errors, `-DADI_ACCEPTANCE=ON`. Run every suite, the window suites and
`ctest -L acceptance`. Write what fails on main itself, with file and line: those are findings, not
yours to explain away.

## 2. Every landing stack and chain, as it appears (standing work, first every time)

Fetch before each item. For each new head of `origin/land/basics-*` and of `origin/basics/*-chain`:
build, run the suites it touches, the window suites and the session suite. One table row per head:
branch, head, built or not, what failed.

- A failure that only macOS shows (an exact comparison of a level, a path under `/var` that is a link,
  CoreAudio's first callbacks, a name Apple's compiler refuses) you fix yourself: one commit per fix on
  the branch `basics/mac-chain`, started from the branch that fails, its message naming that branch.
  Win takes the commit into the stack.
- A failure that every platform would show is the author's: write it in your report with the test's
  output.

## 3. The nine steps in the real window, on macOS

The session of ADR-0248 d2: start ADI and choose the audio device; record audio; put an instrument on a
MIDI track and play notes; edit notes; arrange clips (move, copy, duplicate, split, loop); mix (fader,
pan, a send to a return, a group); draw automation; save, quit, reopen and compare; export and compare
the file with what played. The two Windows walk reports show how each step was done and judged:
`adi_daw/collab/walk/2026-11-25-windows11.md` on the branch `walk/windows11`, and its Windows 10 twin on
`walk/windows10`.

- Run the built app with `ADI_HOME` set to a folder of its own, so nothing of the user's is touched.
- Drive the window with what this Mac allows: scripted clicks and keys through the system's
  accessibility interface, the app's own `--smoke-output` picture, its command line. If the system asks
  for a permission you cannot grant, say so in the report and do the steps that need none.
- No microphone is needed: feed the input from a virtual audio device if one is installed, and say so.
  Play live notes through the system's own virtual MIDI bus.
- Judge sound by capturing the output and measuring it, as the Windows walks did, not by assuming.
- **Your walk report:** `adi_daw/collab/walk/2026-11-27-macos.md` on the branch `walk/macos`, in the
  shape of the Windows reports: one row per step with what was done, what happened, pass or fail.
  Number each fault M1, M2 and on. Fix what you can prove, each on `basics/mac-chain`; leave the rest
  for win, who gives the register ids.
