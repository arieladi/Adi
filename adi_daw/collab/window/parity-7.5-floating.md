# Parity checklist — step 7.5, the floating-window host

Drafted by the window lane (ADR-0208) from the Live 12 manual (`live12-manual-en.pdf`, the PDF's
pages), STEP-7-PLAN 7.5 and ADR-0180 d3, d7, for win to run against Live 12 (ADR-0108). Rows
describe the behaviour in our words. Status as in `parity-7.2-shell.md`.

| # | Live's behaviour | Manual / ADR | ADI in this PR | Status |
|---|---|---|---|---|
| 1 | A plug-in's own window floats, opened from the wrench toggle in its title bar | §23.3, p. 461–462 | The wrench sits before Configure on a plug-in device's title bar, never on a device of no plug-in, lit while its window is open. A click opens the plug-in's hosted editor (`createEditorComponent`, #391) in a floating window titled track/device, at the plug-in's own size, not resizable, with no maximise; a second click closes it. One window at a time unless Ctrl/Cmd is held or Multiple Plug-In Windows is on; a plug-in with no editor refuses before any other window closes, with its reason in the Status Bar; an editor's error, and an editor the plug-in drops (its window then closes), reach the Status Bar. Auto-Hide Plug-In Windows shows only the selected track's; Plug-in windows always on top is followed. The editor is torn down before its window | built (D3, `window/plugin-window`, N8). Not followed: Auto-Open Plug-In Windows, since nothing in the window inserts a device yet. Real drawing, native parenting and HiDPI wait for win's desktop check |
| 2 | Ctrl/Cmd+Alt+P hides and shows every open plug-in window; Ctrl/Cmd on the toggle opens several | §41.4, p. 987 | View > Hide Plug-In Windows / Show Plug-In Windows on Ctrl/Cmd+Alt+P, after Device View: every plug-in window hidden, open still, then shown again as Auto-Hide allows; a window opened on purpose while they are hidden shows them all. Ctrl/Cmd on the wrench keeps the others open | built (D3) |
| 3 | Undocking moves the same view into a window and back, never a copy | ADR-0063 d1, ADR-0180 d3 | `FloatingHost::detach` reparents the component; closing docks it at its exact bounds | built |
| 4 | A second view of one model, both alive at once (the analyser's docked panel and its big window) | ADR-0116 d1/d4, ADR-0183 d4 | `FloatingHost::openView` with a shared `AnalyserModel`; both views read one measurement | built |
| 5 | A window reopens where it was, on the same monitor, clamped to the screens there are now | SPEC §8.4 (MUST) | The rectangle and the monitor's identity are kept in `ui_view`; a lost monitor clamps onto one that exists | built |
| 6 | Each window has its own frame clock | ADR-0180 d1 | One `VBlankAttachment` per floating window; its drain counts its own frames | built |
| 7 | Keys work in every window: Space stops the transport from a plug-in window too | ADR-0180 d6 | A floating window's keys go to the application's command layer | built |
| 8 | Deleting a device closes its window; undo brings the device back, not the window | ADR-0180 d7 (the director's ruling) | The host polls the device's retirement each frame; the closed state is saved | built |
| 9 | Floating tooltips in every window | ADR-0203 d12 | One tooltip window per floating window | built |
| 10 | A floating window's interface zoom | ADR-0203 d6; ADR-0129 d3 | Ctrl/Cmd + and - in an ADI view's window (Channel EQ, the analyser) zoom that window alone, between 50 % and 200 %, as the main window's; every other key there is still the main window's. Plug-in windows are never scaled by ADI | built (`window/window-zoom`): kept in the App settings' `window.zoom` as `floating:<key>@<display>` on every step, and the window opens again at it on that display (N4) |
| 11 | The analyser's big window | ADR-0183 d4 | The view and its shared model are built and tested; nothing opens it until the analyser device (the devices lane's) declares its second view. #204's per-device "Analyse" button is gone: Live has none | open |
