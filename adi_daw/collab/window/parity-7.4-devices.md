# Parity checklist — step 7.4, the device strip and the DAW-drawn panel

Drafted by the window lane (ADR-0208) from the Live 12 manual (`live12-manual-en.pdf`, the PDF's
pages), for win to run against Live 12 (ADR-0108). Rows describe the behaviour in our words.
Status as in `parity-7.2-shell.md`: built, partial, open, measure.
"Online §" cites Ableton's online Live 12 manual (ableton.com/en/live-manual/12/, the
2026-10-01 edition); see `parity-7.2-application.md`.

| # | Live's behaviour | Manual / ADR | ADI in this PR | Status |
|---|---|---|---|---|
| 1 | The Device View shows the selected track's chain, devices left to right | §3; §23, p. 443 | The strip follows the arrangement's selected track; devices left to right; it scrolls sideways, never down | built |
| 2 | The Device View has one height; ADI lets the strip grow upward only, from a floor of Live's height | ADR-0184, ADR-0203 d7 | Floor 169 units (unverified), a desktop default; the top edge drags it taller; the ceiling leaves the transport, the ruler and one row | built; measure the 169 |

| 10 | A parameter's value reads in the plug-in's own words | ADR-0198 | `DeviceInstance::paramText` through the publication | built |
| 11 | Automated parameters are marked; an overridden one too | §21; ADR-0162 | The automation LED: a red dot while the control follows its lane; OFF (a dim grey dot) while overridden, as manual 25.4 says the LED goes off (ADI showed orange there until `window/automation-arm`); a drag on the control puts it out with the first value the plug-in takes, and the control bar's Re-Enable Automation lights it again at once (parity-7.2 row 32). A CLAP plug-in's control finds its lane under the lane's decimal ref (ADR-0165), as the session's override does, so the two indications agree for every format | measure the LED's lit red, its unlit grey and the mark's place against Live's |
| 12 | Dragging a control changes the parameter, one undo step per gesture | ADR-0124 d4, ADR-0181 d5; MR 9.1 | The control sends a bounded begin/value/end gesture; the document hands it to the engine's window producer (`ParamOps::uiEvent`, N7): every value reaches the plug-in at once, End commits ONE undo step named for the device and its control, its first-touch opener in front, and a value nothing brackets closes on the drain's quiet timer. A refusal (a device not loaded, a parameter the plug-in has not or does not let be edited, a value it did not take) goes to the Status Bar with its reason. The step is named by the engine's label, the device and its control ("UI knobs: Cutoff"), which the Edit menu shows (`window/strip-param-undo`) | built; open: an undone or redone value reaches the plug-in only at the next load (N44, window log). Measure Live's undo label for a control drag (with A5, the Undo History window) |
| 16 | The value keys on a clicked control (manual 41.6): Return to Default is Delete; Shift while dragging is finer resolution; the up and down arrows decrement and increment, with Shift in octaves or fine; 0 to 9 type a value, Enter confirms it and Esc cancels | §41.6, p. 989 | A click on a control gives it the focus (the slider declines it). Delete or Backspace is one bounded gesture to the plug-in's declared default (`ParamDescriptor::defaultValue`, through the feed's `defaults`): one undo step, an opener in front when the parameter was never touched; the device's own Delete (row 6) stays with a focused title bar. Shift while dragging swaps JUCE's velocity mode in: slow movement under Shift moves the value by a fraction of a plain pixel and speeds up with the mouse (`window/strip-param-undo`) | partial: Delete built; Shift built as JUCE's velocity mode, not Live's fixed ratio (measure Live's ratio and whether the pointer stays); the arrows, typed digits, Enter and Esc open |
| 13 | The mouse wheel over a control only scrolls | ADR-0203 d11 | Sliders ignore the wheel | built |
| 14 | An Airwindows suite device shows only its active algorithm's controls | ADR-0198 | `panel::activeAlgorithmParams` | built |
