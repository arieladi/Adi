# ADI window walk on macOS, 27 November 2026

Apple Silicon, macOS 26.6.2 and a native Debug build of `90f4091d241d1ae4b8690e74fafd1124d4611f0c`. The test instance used its own `ADI_HOME`. BlackHole 2ch carried the test signal and digital output capture. The control loop delivered a 440 Hz tone at −29.03 to −29.04 dBFS RMS on both channels. Live MIDI uses a temporary system CoreMIDI source.

## Nine steps

| Step | What I did | What I saw | Expected | Result | Finding |
|---|---|---|---|---|---|
| 1 | Launched the app bundle with an isolated home, made a new set with Cmd+N and opened Audio Settings. Changed the output and selected BlackHole again on both sides. | Untitled(2) opened. Settings showed CoreAudio, BlackHole 2ch input and output, 48 kHz, 512 samples, and 10.67 ms input and output latency. ## Findings

- **M1 / SC-392 — silent audio input.** macOS TCC refused the app's request for microphone-service authorization because its bundle lacked `NSMicrophoneUsageDescription`. The virtual input uses the same permission as a physical input. The app target is declared at `src/juce/ui_shell.cmake:127`. The known signal and refusal were reproduced with the native bundle.
