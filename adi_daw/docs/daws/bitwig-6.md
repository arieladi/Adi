Current scope (milestone 9): MIDI/Note FX, modulators, containers, non-instrument audio devices and The Grid are included. Poly Grid is examined only for shared patch/voice/host semantics; other built-in instrument devices remain excluded. Earlier exclusions below describe historical passes. This is research and feasibility analysis, not product implementation or a new ADR.

## Bitwig MIDI, devices and Grid feasibility — milestone 9

This pass adds 173 source-bound contracts, each with an ADI implication and an unexecuted test. No Grid algorithm or preset compatibility is claimed from module names.

The useful architectural direction is a native ADI feature using existing Pd and native DSP capabilities together. Keep routing, event/voice ownership, parameter identity, transactions, latency and lifecycle in the host. Use Pd for user-authored patches and suitable DSP; reuse registered built-in native kernels for demanding processing. This is a feasibility recommendation under existing decisions, not an instruction to build a second graph engine or replace the chosen plugdata editor.

### Native ADI versus Pd: feasibility and current implementation boundary

This comparison distinguishes approved direction, inspected source and separate lane work. Research tree 8955b800 retains product baseline 5c9e1cd8; the user's checked-out tree is 9bd55a8e. The separate codex/midi-effects tip c130f0e7 contains relevant work absent from both inspected product snapshots. Local branch evidence does not establish the state of every remote lane or ORC-VST checkout. Full code paths/hashes and limitations are in private E54/pd-feasibility.md and implementation-status.json.
