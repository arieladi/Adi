# Mix functions and shared analysis

This continuation of the actual-chain foundation implements ADR-0236/0237's opt-in device-area functions and the shared analyzer/tap boundary. It does not add reserved channel slots. Win reviews and merges the slices; native interaction acceptance belongs to the director's separate tester.

## Processing and editing

`mix_functions` identifies five canonical **internal** device references. An ordinary VST3/CLAP with the same name or UID remains an ordinary plug-in. The device-area `+` menu checks the owning channel for existing functions and asks the linked factory which cores are available. Unavailable functions have a named refusal; they never instantiate pass-through DSP under an enabled processor label.

Prepared insertion and movement use existing journal operations, an expected history head and the authored device ID. A function can move among ordinary devices in its owning channel. Default insertion affects only the contiguous function tail: EQ first, newly added middle functions in addition order, Limiter last. Later additions preserve manually chosen positions. Off/removal uses `device.remove`; one Undo restores the function, its state and its parameter records. Native Duplicate and duplicate clipboard-paste are refused. Ordinary plug-in bypass/clipboard behavior is unchanged.

Inline controls use the same `ParameterFeed`, exact runtime token and presentation stamp as STACK. Begin/value/End use `ProjectDocument` and `ParamOps`, with no private undo log. Hiding, detaching, minimizing, removing or replacing the editor ends/cancels its retained gesture and invalidates delayed menu actions.

The linked native L function now has two independently enabled pages in fixed audio order **Clip → Limiter**. The application loader injects the full backend through `withFullMixFunctions`; the standard-library-only loader retains a clearly identified limiter-only tier. The full backend uses the authored ADI-Clip and ADI-L cores through `adi_mix_clip`, `adi_mix_limiter` and `adi_mix_limit_chain`, without launching a plug-in instance or editor. The limiter component has no JUCE or plug-in SDK dependency; the Clip implementation has an optional JUCE DSP dependency behind a standard C++ interface. The other four function references remain unavailable until their processing adapters are linked, rather than substituting pass-through processors.

The initial state has Limiter enabled and Clip disabled; the selected parameter page starts at Limiter while the physical tab order stays Clip → Limiter. Selecting a page changes only presentation. Each page's power control edits its own real parameter through the common gesture path, so both stages may be on, off, or independently enabled without discarding settings. Disabled stages retain state and process no audio frames. Removing the containing function remains distinct from switching either stage off. Controls with no page metadata keep the existing panel layout.

Channel roles are explicit prepared data. The current combined DAW adapter admits mono/stereo and refuses layouts it cannot yet describe; the underlying limiter retains its surround grouping. Floating-point operations, float FFT/convolution paths and target-specific ISA dispatch remain the authored engines'. AVX is compiled in a separate object with runtime admission; it is not a global architecture requirement. The composition delays an external limiter key by Clip's admitted latency when necessary. Main/Info analysis owns display demand: the processing cores do not start their own waveform or loudness displays.

Stable decimal parameter IDs use the existing device event protocol. The full controller retains **74 raw state values and exposes 67 descriptors**: nineteen limiter sound controls at `0..18`, independent stage enables at `19` and `20`, the Clip parameter range at `21..72`, and the limiter export policy at `73`. Seven Clip presentation/coupling values are preserved in state but are not advertised as working controls in this basic page tier: loudness target, visualizer zoom, global gain link and four band gain links. The limiter-only tier exposes its own 21 descriptors and never advertises a Clip page. Physical values/defaults and nonlinear time mappings are the engine adapter's, including stereo link limits.

Latency/shape controls are editable configuration, **not automation**: limiter Style (`1`), Lookahead (`2`), Oversampling (`7`), True Peak (`8`), stage enables (`19`, `20`), Clip online/export quality (`71`, `72`) and limiter export policy (`73`). `ParamDescriptor::configurable` admits them to `ParamOps::uiConfigurationEvent`; owned Begin/value/End, journal transaction, undo, cancellation and restoration remain common. Ordinary non-automatable descriptors remain read-only. The feed distinguishes `modifiable` from `automatable`; configuration changes neither arm nor override a lane. Old automation events for these controls are ignored in playback and export, so they cannot start a latency transaction inside an export. Other sound controls retain automation. Retained controls still validate the exact runtime token and presentation stamp before editing.

Prepared limiters share one process-wide background owner, which parks on an event rather than polling. Structural preparation, retired instances and genuinely changed smoothing kernels request coalesced work. A kernel blocked on audio admission retries after actual audio progress; the owner never schedules an idle retry. Registration/destruction occur off audio and wait for any in-flight owner callback before releasing its context. Wake and dispatch counters are taken before no-work exits so idle tests detect a polling regression. Enabled processing remains independent of editor visibility.

Before the owner claims a latency offer, newer structural intent may replace or cancel it. A claimed offer must settle with the graph: conflicting manual configuration/state changes are refused before stored values change, and idempotent changes remain accepted. Ordinary sound controls remain editable. This prevents an accepted off switch from later admitting an older on offer while preserving the graph's compensation contract.

State validates completely before publication, rejects non-finite/out-of-range values and preserves future unknown top-level state fields. Version 2 records the stage topology, backend capability and all authored raw values. It retains the Clip continuation hint for a fresh instance or isolated export, while a live preset/undo recall keeps active processing history. A limiter-only build refuses a saved state requiring Clip processing and reports that capability as unavailable.

Quality and stage-enable changes use the combined latency acknowledgement. `NodeIo::renderBlock` identifies one physical callback across every event/transport segment. `configuredLatency` is the graph publication's cached device latency. The composition admits a prepared stage configuration only at a new physical callback carrying its total latency, then pins the block context across all segments. The advertised limiter target stays fixed after acknowledgement while its old bank fades. No callback asks a plug-in SDK for its current latency.

In-place graph retaps now publish a complete compensation plan instead of changing live line targets from the owner thread. The audio boundary admits node latencies, arrivals, main/side/dry delay targets and event/tap timing together, before transport reads the applied graph latency. An unavailable larger ring is allocated off-thread and primed at the old audible target; the old plan stays active until the resources required by the new plan are ready. Event/transport segments within one physical callback retain the same plan. The bounded atomic snapshot and prepared scratch do not allocate, lock or query devices on the callback. This replaces immediate partial retap application and needs the engine review alongside the function integration.

Export quality has explicit end-to-end intent: `SessionSpec::exporting` reaches the device request before preparation, and `NodeIo::exporting` accompanies processing. The offline render queue sets that intent. Offline analysis and performance-state choices do not implicitly select export quality. The first export block therefore starts with its chosen Clip quality and optional limiter 32x policy, rather than waiting for an audio callback to guess the mode. The render queue consumes stored state; a future live export UI must capture current runtime continuation before creating its isolated render session. Still's placement and later core presentation choices remain outside this slice.

## Shared analyzer contract

One process-wide worker sleeps until visible windows request a frame. There is no document/view polling analysis thread. Compatible consumers share a source cursor, overlap window, FFT plan and immutable result. Scope, meters and phase skip FFT unless a compatible spectrum/spectrogram consumer needs one. Spectrum calibration uses the existing DAW spectrum kernel; the basic meter is sample peak/RMS, not a second true-peak/loudness implementation. Persistent loudness remains the existing Main service, rather than a loudness engine on every channel row.

The new Analysis tab is appended at index 5; stored indices 0–4 keep their meanings. It supplies Spectrum, Scope, Meters, Phase and Spectrogram views, Main/Selected sources, tap/channel selectors, Freeze, local Reset and a following analyzer window. Info reuses the same broker. Expanding the default Main analyzer preserves the current editing channel. Reset affects only that view's interval, not audio or another consumer. Freeze/hide releases demand. Spectrogram raster updates are bounded and cached per source epoch/revision.

Work per pass is bounded by 16 analysis windows, 262144 input samples and 256 cursor reads. Domain order rotates between passes so one backlogged source cannot always take the first budget. Results expose source/storage epochs, heard timestamps, hop size, gaps, overrun, non-finite visualization samples and remaining backlog. A missed interval is not relabelled as continuous current data.

The current views use 1024-sample Hann windows and an `N/4` hop. Scope displays an untriggered stereo interval, Phase displays the stereo vectors and L/R correlation, and Meters displays that interval's sample peak/RMS without independent meter ballistics. Spectrogram retains at most 128 hop columns and aggregates bins into logarithmic display rows. Channel selection applies to spectral analysis; Scope/Phase and the per-channel meters retain raw L/R. Engine APIs expose individual device input/output sources, but the current pane's tap selector offers the three channel taps only. These basic modes do not implement every future analyzer setting, reference curve workflow, trigger mode, loudness standard or native product control.

## MX-30 capture boundary

`ScopeSource` names a channel tap or a particular authored device's input/output. `ScopeLease` negotiates history and follows source, rate and history generations. Each reader has an independent sequence cursor; it receives explicit not-ready, generation-change, overrun or discontinuity status. Logical one-sample automation segments coalesce into contiguous timestamp spans rather than exhausting the timestamp ring.

Capture observes the graph's effective active/bypass/suspended signal at float32 or float64 without modifying it. Heard timestamps use the cached graph compensation and device latency. Multiple logical sources at the same physical port share one writer. Last release disables capture, independently of enabled processing lifetime.

Prepared capture publications retain buffers and independent port-state owners. The audio thread adopts a publication only at a physical callback boundary; collection obeys the publisher's strict epoch. A stalled callback keeps its old storage alive, and detaching a retired node never dereferences that node. The callback does not allocate, lock, change shared ownership or destroy a capture buffer.

## Validation and remaining gates

The component suites cover prepared operations/undo, stale identities, gesture cleanup, independent cursor/history/rate changes, stalled-callback retirement, effective signal capture, shared analysis demand/budgets and processor adaptation. Software peers have no native handle. Audio extraction comparisons use frozen authored suite engines in a separate private harness; native-reference research and observations do not enter public tests.

Live visual/mouse/menu acceptance remains a separate trailing gate. New CPU timing is deferred at the director's request: structural demand counters and unchanged arithmetic do not establish a new percentage. The current adapter processes float audio; combined surround/double-precision admission and the unavailable function adapters remain separate work. Compensated external device keys still depend on DEV-05/MX-24; analysis taps are not a substitute audio sidechain route. No VST3/CLAP release or live native visual acceptance is implied by these integration tests.
