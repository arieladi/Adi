# Whole-feature DAW research coverage — v0.3, 2026-11-04

The director explicitly clarified that the early Cubase/Live/Bitwig examples were only examples. This register decomposes all 15 Dream Reference sections into research requirements, including ADI-only features. Current FEATURES/DECISIONS govern implementation; Dream expands research scope without silently superseding decisions. Built-in reference instrument/effect implementations remain excluded. Hosting, routing, editor utilities and modulation remain included.

**Inventory is not completion.** Every row below is open. A row closes only for an identified contract/build after source, ownership, state transitions, undo, persistence, failure and relevant timing/numerical behavior have evidence. IDs are stable in this version; composite requirements need further decomposition as evidence arrives. No finite inventory guarantees every future need.

The per-app files contain behavior claims and exact manual pages. This register names requirements and points to their relevant evidence, without asserting that a reference app implements an ADI-only idea. New whole-host tests are in private `WHOLE-HOST-MISSIONS.md`; SDK contracts and cross-source contradictions are in `DAW-RESEARCH-INTEGRATION.md`.

The director's subsequent base-reference clarification extends Live research beyond Dream examples: [ableton-12.md](daws/ableton-12.md) now includes the A-BASE contents inventory and completion dimensions for all host topics. C4 in [cubase-15.md](daws/cubase-15.md) expands export capability contracts; B4 in [bitwig-6.md](daws/bitwig-6.md) establishes the documented version-6 Auto-zoom feature and its measurement gaps. The 220 Dream rows below remain open; the 610 Live host/integration contents entries are a separate index, not another feature count or completion claim.

## Scope reconciliation and missing evidence

- Dream’s clip-local attribution for Live tuning is contradicted by the local Live manual’s Set-wide tuning; ADI’s per-key-change tuning remains the existing plan.
- REAPER documents optional saved undo and alternate paths, so persistent/branching history is not wholly unprecedented. ADI attribution and collaboration still require their own design.
- FEATURES has a Score Editor row while §11 explicitly excludes a notation-first workflow; treat engraving-data preservation as in scope and flag the conflicting row for win, without starting a notation editor study.
