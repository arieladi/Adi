How it works

Take the times straight from your rekordbox cues. Cue in is where you start the track (hot cue A), and Cue out is where you start the next track (hot cue C) — so the mix time between tracks is counted in the set.

Play Time = Cue out − Cue in (here 5:31.1), and Set time is the running length of the whole set.

Time formats: 5:57.5 (rekordbox, tenths), 5:57, 5.57 (5 min 57 s, like the old Excel), 5.57.5 (Excel style + tenths), or 1:02:37.

▶ opens the track in a new tab — a YouTube search for the track name by default, or any link you set with ✎ (YouTube, SoundCloud, …). Rename the list with the ✎ next to its name.

Move a track: grab its ⠿ handle and drag it to a new place, then confirm with OK. ↶ / ↷ undo and redo any change — each list remembers its last 2000 changes on this device, even after a reload, so you can step all the way back to the first one and forward again.

Start / End: two markers — lines across the list — bracket the part of the set you plan to play: Start before the first track and End after the last one, with the time on it. Drag either up or down (on a touch screen: by its ⇕, or press and hold it first — a quick swipe just scrolls) to the track you plan to start or end with: the tracks in between light up, and the End shows how long the set plays from the start of the Start track to the end of the End track, and #from → #to. The Start never goes below the End. The S → E box shows the same time; tap it to jump to the End, or its ✕ to put both back round the whole list. With a marker selected, ↑ / ↓ move it one track, Home / End jump as far as it can go.

History: ⋯ → 🕘 History… (or a click on the save status) shows every version of the list saved to GitHub — by any user, on any device — oldest at the top, newest at the bottom, each with who saved it, when, and what changed. It works like Start / End: the End marker picks the version shown (drag it, tap a version, or ↑ / ↓), and the Start marker the version it is compared with — on its own the one just before (auto, it follows the End); drag it to compare from further back, and its ↺ auto puts it back. The list then shows that version, read-only, with the changes marked: a changed value is highlighted with the old one struck through, new tracks say NEW, removed ones stay as struck-through ghosts, moved ones say where they came from; ↓ Next change jumps from one to the next. Restore as new list makes a copy of that version as a new list — the list itself never changes. Close with ✕, Esc or Back.

Users: Public is open to everyone. Log in (👤 button) with a username and password for your own lists — accounts are made by Adi. You log in once per device: it stays logged in — reloads, new tabs, a restart — until you log out (👤 → Log out), and logging in or out in one tab does it in the others too. Up to 100 lists per user, 500 tracks per list.

Lists autosave — there is no Save button. Every change is kept on this device at once and saved to GitHub half a minute after you stop typing (no setup needed); the status next to the set time shows Saving…, All changes saved, or — offline — that your changes wait on this device. A save never goes over a newer one from another device: that version is shown, and yours is kept as a list of its own, “… (conflict …)”.
